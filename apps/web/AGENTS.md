# Siftify Web

React/TypeScript music application built with Vite, TanStack Router/Query, HeroUI, Tailwind CSS and Zustand. This package is `apps/web`; the separate API is in `../api`. Read `DESIGN.md` for the existing UI and icon conventions.

## Commands

Run from `apps/web` with Bun (root `package.json` pins the package manager version):

- `bun install` — install web dependencies; configured, not run during this documentation update.
- `bun run dev` — Vite development server on port 3000; verified in the current environment.
- `bun run build` — TypeScript project build followed by Vite production build; verified (exit 0).
- `bun run typecheck` — `tsrs --noEmit`; verified (exit 0).
- `bun run lint` — type-aware Oxlint; verified (exit 0).
- `bun run format:check` — Oxfmt check; verified but currently exits 1 on existing `package.json` and `tsconfig.json` formatting. Do not reformat unrelated changes to make it pass.
- No web test script is defined in `package.json`; do not assume a configured test suite.

Root `lefthook.yml` runs web lint/format checks on staged files at pre-commit and web typecheck at pre-push; consult it for the exact glob and commands.

## Layout and generated files

- `src/app` holds the entry point, providers and global theme; `src/routes` contains TanStack file routes. Modules live under `src/modules/<Feature>` with their own components/hooks/store/types; reusable utilities, API and UI live under `src/common`.
- `~/` aliases `src/` (`tsconfig.app.json`); feature entry points commonly export from `index.ts`. Oxfmt controls import order, Tailwind class order and formatting.
- `src/app/routeTree.gen.ts` is generated by the TanStack Vite plugin from `src/routes`. Never hand-edit it. `bun run build` regenerates it and validates the resulting TypeScript; it is ignored by Oxlint and Oxfmt.
- `src/common/constants/env.ts` requires `VITE_BASE_URL` to be a valid URL at runtime; `src/common/api/api.ts` adds `/api` and uses cookies. `.env.example` is currently empty; do not print or commit `.env` contents.

## Playback and assets

- `PlayerProvider` owns `AudioEngine` and browser audio events; `player.store.ts` owns playback state and transitions. Manual queue entries have priority over context; `nextIndex` points to the next context track. Previous navigates context, not a playback-history stack.
- Repeat cycles `off → all → one`: all wraps the context without restoring consumed manual entries; one repeats on audio completion, not on explicit Next. Volume and repeat mode are stored in localStorage.
- `public/test` is gitignored, but `LikedSongs.tsx` imports its demo track data. A clean checkout may need those local assets before the app builds or demo playback works; `audioUrl` is temporary.
- Icons use `src/common/ui/Icon.tsx` and `public/assets/icons/sprite.svg`: add a `<symbol id="…" viewBox="…">`, then use `<Icon name="…" />`. Icons inherit `currentColor`; `Icon` is decorative, so label the containing icon-only control. See `DESIGN.md`.
- The current fixed-width sidebars can collapse the main area at mobile widths; do not assume the desktop layout is responsive.
